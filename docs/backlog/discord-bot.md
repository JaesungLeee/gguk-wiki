# 디스코드 봇

> 상태: backlog. 미룬 이유는 [backlog/](README.md)를 따른다.

git이나 Claude Code를 쓰지 않는 사람도 디스코드에서 위키를 쓰게 한다. 봇은 [MCP 서버](mcp-server.md)의 도구를 쓰고, [hosting/](hosting/README.md)의 서버에서 돈다.

## 봇 UX

봇 하나로 자동 라우팅한다. 질문마다 스레드를 만들고, 👍/👎 반응으로 피드백을 받는다. 명령은 `/ask`, `/decision`, `/digest`를 둔다.

## 회의록 업로드 채널

1. 디스코드 `#회의록` 채널에 .md 파일을 첨부한다.
2. 봇이 GitHub App 토큰으로 `raw/meetings/`에 커밋한다.
3. `raw/meetings/**` push가 GitHub Actions의 Ingest 워크플로를 실행해 PR을 만든다. 이 경로의 Ingest는 개인 구독이 아니라 API 키로 실행된다.
4. 워크플로가 디스코드 웹훅으로 결정사항 요약과 승인 요청을 보낸다.

- 템플릿을 지키지 않은 회의록도 거절하지 않고 커밋하되, 정확도 경고를 답글로 남긴다([자유 형식 회의록 처리](../ingest.md#자유-형식-회의록-처리)).
- 봇이 main에 직접 커밋하므로 봇의 App도 ruleset 우회 대상이 된다. ruleset은 경로를 제한하지 못하므로 `raw/meetings/`에 새 파일만 추가하는 것은 봇 코드가 지킨다([main 보호 규칙](../ingest.md#main-보호-규칙)).
- 업로드 전에 [공개 범위](../data-model.md#공개-범위) 검사를 봇에서도 해야 한다. 봇 커밋은 PR을 거치지 않고 바로 public이 되기 때문이다.

## [반영] 버튼

git을 모르는 사람도 디스코드에서 확인을 마칠 수 있게 한다.

- 디스코드 메시지에 결정사항 요약과 "결정 여부 불명확", "추론함", "중복 또는 대체 후보" 항목을 보여 준다.
- 봇은 버튼을 누른 사람이 지정한 역할의 팀원인지 확인한 뒤 App 토큰으로 merge한다.
- 누른 사람을 PR 코멘트로 남겨 확인 기록을 대신한다.
