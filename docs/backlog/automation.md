# 자동화

> 상태: backlog. 미룬 이유는 [backlog/](README.md)를 따른다.

사람이 실행하지 않아도 도는 작업을 모은다. 대부분 GitHub Actions의 schedule이나 서버에서 돌고, API 키나 알림 채널이 필요하다.

## 주간 lint

- 주 1회 오래된 페이지, 모순, 코드 불일치를 검사하고 결과를 리포트로 보낸다.
- 오래됨 검사 대상은 [`durability`](../data-model.md#결정-문서-형식)를 따른다.
- 권장 모델은 Opus다. 버전은 도입할 때 최신으로 정한다.

## 변경 알림

- 결정이 merge되면 영향받는 직무(`platforms`)에 변경을 알린다.
- 위키 정책과 코드가 다른 것을 lint가 찾으면 관련 직무에 알린다([진실의 기준](../data-model.md#진실의-기준-source-of-truth)).
- 열린 Ingest PR이 48시간 동안 merge되지 않으면 작성자에게 리마인드한다.
- 알림 채널은 디스코드 웹훅을 쓴다.

## PR 리뷰 봇

코드 레포 PR에서 관련 정책 위반 여부를 검사한다. [MCP 서버](mcp-server.md)의 도구를 CI에서 쓴다.
