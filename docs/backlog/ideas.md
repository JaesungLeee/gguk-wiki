# 확장 추천 사례

> 상태: 후보. 설계에 넣을 때는 해당 문서에 규칙을 적고 `설계 위치` 열에 위치를 남긴다.

`설계 위치` 열은 이미 설계가 있는 사례의 위치를 가리킨다. 1단계 문서이거나 backlog 문서다. 비어 있으면 아직 설계가 없는 후보다.

| 분류 | 사례 | 해소되는 피로 | 설계 위치 |
| --- | --- | --- | --- |
| 변경 전파 | 결정 변경 시 영향받는 직무(Android/iOS/서버/디자인)에 자동 알림 | "그거 바뀐 거 몰랐어요" | backlog: [변경 알림](automation.md#변경-알림), [훅](hooks.md) |
| 변경 전파 | 개인화된 주간 다이제스트 | 모든 회의록을 다 읽어야 하는 부담 | |
| 정합성 검사 | 기획서 ↔ 회의 결정 ↔ 코드 사이 모순 탐지 | 문서끼리 서로 말이 다른 상황 | |
| 정합성 검사 | Android ↔ iOS가 같은 정책을 다르게 구현했는지 비교 | 클라이언트 간 동작 차이 | |
| 정합성 검사 | 오래된 페이지 감지 후 담당자 확인 요청 | 위키가 낡아 가는 문제 | backlog: [주간 lint](automation.md#주간-lint) |
| 개발 흐름 연계 | PR 리뷰 시 관련 정책 위반 여부 체크 | 리뷰어가 정책을 다 기억해야 함 | backlog: [PR 리뷰 봇](automation.md#pr-리뷰-봇) |
| 개발 흐름 연계 | 기획서·정책으로 QA 테스트 케이스 초안 생성 | 테스트 케이스 반복 작성 | |
| 개발 흐름 연계 | 회의 결정사항으로 이슈 티켓 초안 생성 | 회의 후 정리 작업 | |
| 회의 효율 | 회의 전 브리핑 (관련 과거 결정, 미해결 이슈, 지난 액션 아이템) | 매번 처음부터 맥락 설명 | |
| 회의 효율 | 액션 아이템·미결 질문 추적 (담당자, 기한) | 결정은 했는데 아무도 안 함 | 1단계: [액션 아이템 형식](../data-model.md#액션-아이템-형식), [섹션별 반영 위치](../ingest.md#섹션별-반영-위치) |
| 사람 이동 | 신규 투입 인력 온보딩 가이드 자동 생성 | 같은 설명 반복 | |
| 사람 이동 | 인수인계 문서 생성 | 퇴사·이동 시 지식 유실 | |
| 용어 통일 | 도메인 용어집 (기획 용어 ↔ 코드 변수명 ↔ DB 컬럼) | "기획의 '정산'이 코드의 뭐예요?" | 1단계: [위키 구조](../data-model.md#위키-구조), [질의 정규화](../retrieval.md#질의-정규화) |
| 지식 선순환 | 답하지 못한 질문을 지식 공백 리스트로 만들고 담당자 배정 | 위키가 실제 수요를 못 따라감 | backlog: [report_gap](search-upgrades.md#report_gap) |
| 지식 선순환 | 좋은 Q&A 답변을 위키 페이지로 저장 | 같은 질문 반복 | |
