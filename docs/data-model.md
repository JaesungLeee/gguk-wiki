# 데이터 모델

위키에 무엇을 어떤 형식으로 저장하는지 정한다. 저장 흐름은 [ingest.md](ingest.md), 조회 흐름은 [retrieval.md](retrieval.md)를 따른다.

## 진실의 기준 (Source of Truth)

| 영역 | 기준 |
| --- | --- |
| 정책·의도 | 가장 최근의 유효한 결정(`decided`). 위키 페이지는 그 결정의 요약본 |
| 화면 디자인 | Figma. 위키에는 디자인 결정만 남기고 화면 정의는 옮기지 않는다 |
| 실제 동작 | 코드 (각 레포의 default 브랜치) |
| 서로 다를 때 | 자동으로 고치지 않는다. 위키와 코드가 다르면 조회 답변에 불일치로 표시한다([답변 형식](retrieval.md#답변-형식)). 기획 문서와 디자인 결정이 다르면 ingest할 때 표시한다([중복·충돌 확인](ingest.md#중복충돌-확인)) |

## 위키 구조

직무별이 아니라 도메인별로 나눈다. 한 페이지에서 서버/Android/iOS에 공통인 정책을 볼 수 있다. 플랫폼별 구현 위치는 위키에 적지 않고 조회할 때 코드에서 찾는다([코드 조회](retrieval.md#코드-조회)).

```text
gguk-wiki/
├── raw/                                     # 원본, 수정 금지
│   ├── meetings/2026-11-10-결제-정책.md     # 회의록 (파일, 노션 페이지, STT 요약)
│   ├── specs/2026-11-05-정산-기획.md        # PRD, 스펙 문서
│   └── notes/2026-11-11-환불-기한.md        # 채팅으로 받은 내용
├── wiki/
│   ├── domains/payment.md                   # 정책 요약, 미결 목록
│   ├── decisions/2026-11-10-환불-기한.md     # 결정 1건 = 파일 1개, 상태와 이력 포함
│   ├── glossary.md                          # 직역으로 찾을 수 없는 기획 용어 ↔ 코드 심볼명
│   ├── action-items/meetings/2026-11-10-결제-정책.md  # 원본 1건의 액션 아이템 = 파일 1개
│   ├── action-items.md                      # 자동 생성, 직접 수정 금지
│   ├── index.md                             # 자동 생성, 직접 수정 금지
│   └── log.md                               # 자동 생성, 직접 수정 금지
├── scripts/                                 # 인덱스 생성·형식 검사(CI), setup-workspace.sh(개발자 PC)
├── plugin/                                  # Claude Code 플러그인 (ingest, ask 스킬)
├── .claude-plugin/marketplace.json          # 플러그인 마켓플레이스 등록
├── .github/workflows/                       # 형식 검사, 인덱스 재생성
├── AGENTS.md                                # 위키 운영 규칙 (스키마): 도메인 목록, ingest·조회 절차
└── CLAUDE.md                                # `@AGENTS.md` 한 줄
```

`scripts/`는 [인덱스 생성과 형식 검사](ingest.md#인덱스-생성과-형식-검사)와 [작업 공간](plugin.md#작업-공간), `plugin/`과 `AGENTS.md`는 [plugin.md](plugin.md)를 따른다.

**원본 자료 (`raw/`)**

| 폴더 | 내용 |
| --- | --- |
| `raw/meetings/` | 회의록. 마크다운 파일, 노션 페이지, STT 요약([입력](ingest.md#입력)) |
| `raw/specs/` | PRD, 스펙 문서 |
| `raw/notes/` | 채팅으로 받은 내용. ingest 스킬이 받은 말을 그대로 파일로 만든다 |

- 파일 이름은 `YYYY-MM-DD-제목.md`로 한다. 노션 내보내기처럼 이름이 규칙과 다른 파일은 옮기면서 이름만 바꾸고 내용은 그대로 둔다.
- `raw/`의 파일은 넣은 뒤 고치지 않는다. 모든 결정의 `source`가 손대지 않은 원본을 가리키게 하기 위해서다.
- 기획 문서가 고쳐지면 기존 파일을 바꾸지 않고 새 파일로 다시 넣는다.
- 1단계는 마크다운만 받는다. 노션 페이지와 STT 요약도 마크다운으로 저장한다.

`raw/notes/` 형식:

```markdown
---
date: 2026-11-11
author: JaesungLeee          # 말한 사람의 GitHub 아이디
domains: [payment]
---
환불 기한 7일로 확정됐어. (받은 말 그대로)
```

**도메인 목록 고정**

- 도메인 목록은 `AGENTS.md`에 고정한다. 이름은 영어 소문자와 하이픈으로 쓴다. 예: `payment`, `push-notification`
- 목록에 없는 도메인이 필요하면 목록 추가 PR을 먼저 낸다.
- `payment`, `payments`, `결제`처럼 같은 도메인이 여러 폴더로 갈라지는 것을 막기 위해서다.

**용어집 (`wiki/glossary.md`)**

조회할 때 기획 용어를 코드 심볼명으로 바꾸는 데 쓴다([질의 정규화](retrieval.md#질의-정규화)). 직역으로 코드에서 찾을 수 없는 용어만 적는다.

| 기획 용어 | 동의어 | Node | Android | iOS |
| --- | --- | --- | --- | --- |
| 보관함 | 저장 목록 | `SavedRoom` | `SavedRoom` | `Archive` |

- 직역으로 찾히는 용어(핀 → `pin`, 방 → `room`)는 적지 않는다. 세 플랫폼의 도메인 이름은 대부분 같은 영어 직역이므로, 직역이 아니거나 플랫폼마다 이름이 다른 용어만 적어 관리할 항목을 줄인다.
- 경로는 적지 않고 심볼명만 적는다. 파일을 옮겨도 고칠 필요가 없고, 이름이 바뀔 때만 고친다.
- 넣는 절차는 [용어집 반영](ingest.md#용어집-반영), 이름이 바뀌었을 때의 처리는 [코드 조회](retrieval.md#코드-조회)를 따른다.

## 공개 범위

위키 레포는 public이다. 올라간 내용은 지워도 커밋 이력, fork, 검색 엔진 캐시에 남으므로 넣기 전에 거른다.

| 구분 | 대상 |
| --- | --- |
| 허용 | 참석자 이름, GitHub 아이디, Figma 링크 |
| 금지 | 연락처(전화번호, 이메일 등), 인사·평가·급여 정보, 비밀값(API 키, 토큰, `.env` 내용, 키 파일) |

- 원본에 금지 항목이 있으면 ingest 스킬이 PR을 만들지 않고 멈춘다([흐름](ingest.md#흐름)). `raw/`는 고치지 않는 원본이므로, 업로더가 원본에서 지운 뒤 다시 넣는다.
- 비밀값은 GitHub secret scanning도 검사한다. public 레포에서는 무료로 자동 실행된다.
- Figma 링크는 GGUK 디자인이 외부에 공개돼도 문제가 없어 허용한다.
- 레포에는 라이선스 파일을 두지 않는다. 공개는 하되 재사용 권리는 주지 않는다.

## 결정 문서 형식

결정 1건을 파일 1개로 만들고, 상태와 대체 관계를 frontmatter에 기록한다. 이력이 있어야 "왜 바뀌었지?"라는 질문에 답할 수 있다.

```markdown
---
title: 환불 기한
status: decided                  # decided | superseded
decided_at: 2026-11-10
domains: [payment]
platforms: [server, android, ios]  # 영향받는 직무: server, android, ios, design
source: raw/meetings/2026-11-10-결제-정책.md
supersedes: wiki/decisions/2026-10-02-환불-기한.md   # 대체한 이전 결정. 없으면 생략
superseded_by:                   # 이 결정을 대체한 결정. 대체될 때 채운다
durability: temporal             # permanent | temporal
---
## 결정
## 배경
## 검토한 대안
## 근거
## 영향 범위
```

**상태 값**

| 값 | 의미 |
| --- | --- |
| `decided` (결정됨) | 현재 유효한 결정 |
| `superseded` (대체됨) | 새 결정으로 대체됨. 이력 조회용으로만 남김 |

승인 대기 상태(`proposed`)는 두지 않는다. GGUK에는 기획자나 따로 정한 결정권자가 없고 결정은 팀 합의로 정해지므로, 승인할 사람이 없기 때문이다.

- 회의에서 결론이 나지 않은 안건은 결정 문서로 만들지 않고 도메인 페이지의 미결 목록에 둔다([섹션별 반영 위치](ingest.md#섹션별-반영-위치)). 결정 문서는 내용이 정해진 것만 만든다.
- 확정되지 않은 기획 문서는 넣지 않는다([기존 자료 이관](ingest.md#기존-자료-이관)).

**대체 규칙**

- 결정이 바뀌면 기존 파일을 고치거나 지우지 않는다. 새 결정 파일을 만들고 `supersedes`로 이전 결정을 가리킨다.
- 같은 PR 안에서 이전 결정의 `status`를 `superseded`로 바꾸고 `superseded_by`를 채운다. 기존 결정 파일을 고치는 예외는 이 대체 표시뿐이다.
- 대체 관계는 업로더가 확인한 것만 건다. LLM이 추론해서 자동으로 연결하지 않는다. 잘못 연결되면 유효한 결정이 검색에서 사라지기 때문이다.

**유효 기간 구분 (`durability`)**

| 값 | 대상 | 오래됨 검사 |
| --- | --- | --- |
| `permanent` | 원칙, 용어 정의, 아키텍처 방향 | 하지 않음 |
| `temporal` | 수치, 일정, 외부 정책(스토어 정책 등) | 함 |

1단계에는 자동 오래됨 검사가 없다. 나중에 [주간 lint](backlog/automation.md#주간-lint)를 붙일 때 쓰도록 지금부터 기록해 둔다.

## 액션 아이템 형식

원본 1건의 액션 아이템을 파일 1개로 만든다. 경로는 원본의 `raw/` 아래 경로를 그대로 따른다. 예: `raw/meetings/2026-11-10-결제-정책.md` → `wiki/action-items/meetings/2026-11-10-결제-정책.md`. 회의록, 기획 문서, 채팅 원본의 이름이 같아도 겹치지 않게 하기 위해서다.

`wiki/action-items.md`는 이 파일들로 스크립트가 만든다([인덱스 생성과 형식 검사](ingest.md#인덱스-생성과-형식-검사)). 한 파일을 여러 ingest PR이 함께 고치면 merge 충돌이 반복되기 때문이다.

```markdown
---
source: raw/meetings/2026-11-10-결제-정책.md
domains: [payment]
items:
  - task: 환불 API에 기한 검증 추가
    assignee: 홍길동          # 원본에 적힌 이름 그대로
    due: 2026-11-17           # 없으면 생략
    status: open              # open | done | dropped
---
```

**상태 값**

| 값 | 의미 |
| --- | --- |
| `open` (진행 중) | 아직 끝나지 않음 |
| `done` (완료) | 끝남 |
| `dropped` (취소) | 하지 않기로 함 |

- 담당자는 원본에 적힌 이름 그대로 쓴다. GitHub 아이디로 바꾸지 않는다.
- 완료는 다음 회의록과 채팅 두 경로로 반영한다([액션 아이템 완료](ingest.md#섹션별-반영-위치)).

## 회의록 템플릿

템플릿은 권장 형식이다. 지키면 결정사항 추출 정확도가 높아진다. 형식이 자유로우면 "결정된 것"과 "논의만 한 것"을 헷갈리기 쉽다.

- 템플릿을 지키지 않은 회의록도 받는다. 과거 회의록처럼 다른 형식의 자료도 그대로 넣을 수 있어야 하고, `raw/`는 손대지 않은 원본이어야 하기 때문이다.
- 추출 오류는 업로더 확인 단계에서 거른다. 처리 방식은 [자유 형식 회의록 처리](ingest.md#자유-형식-회의록-처리)를 따른다.

```markdown
---
date: 2026-11-10
attendees: [홍길동, 김철수]
domains: [payment, push-notification]
---
## 안건
## 논의 내용
## 결정사항
## 액션 아이템 (담당자 / 기한)
## 미결 사항
```

섹션별 반영 위치는 [섹션별 반영 위치](ingest.md#섹션별-반영-위치)를 따른다.
